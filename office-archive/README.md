# Office 文件归档 · office-archive

DSH 插件，两个工具，把散落的 Office 文件按「大类 / 项目 / 修改时间」归到一处。

设计上刻意把「规划」和「执行」拆开：**方案是一份数据，确认是一次显式调用**。
模型先给你看树，你点头，它才动手。

## 两个工具

| 工具 | 作用 |
|---|---|
| `office_archive_plan` | 只读扫描，产出归档方案：每个文件去哪儿、是否重名、是否内容重复。**不动任何文件。** |
| `office_archive_apply` | 凭方案 id + `confirm: true` 执行，复制或移动，逐个校验 SHA256，并刷新 `00_索引/` |

## 两种用法

1. **收件箱 → 归档**：`sources` 与 `target` 不同，把散落文件搬进归档库。
2. **原地整理**：`sources` 与 `target` 是同一个目录，只挑出「还没归位」的文件
   （根目录下的、以及 `99_未归类/` 里的），放进对应子目录。
   已归位的不动，所以可以每周重复跑。原地整理强制 `move`。

## 对话示例

不用记参数名，这样问就行：

```
把 D:\下载\待整理 里的 Office 文件收进 D:\归档
```

→ 调 `office_archive_plan`，返回一棵「每个文件去哪儿 / 是否重名 / 是否内容重复」的方案树：

```
01_课程作业/程序设计实验/
  实验报告-第3次.docx        ← 根目录
02_课程资料/控制系统/
  第4章.pptx                ← 根目录
99_未归类/
  B企业产品价格表.xlsx       ← 没有命中规则
```

觉得没问题就说「执行」，模型调 `office_archive_apply` 带方案 id + `confirm: true`。
想改分类就说「xlsx 都放到 01_课程作业/表格分析」，它会带自定义 `rules` 重新出方案。

```
把 D:\归档 原地整理一下
```

→ `sources` 与 `target` 都是 `D:\归档`，只捡还没归位的文件，强制 `move`。

```
先看看 D:\归档 里有什么，别动
```

→ 只出方案不动手。方案 6 小时后失效，不执行也没关系。

## 分类规则

`rules` 按顺序匹配，第一条命中生效；键值里出现任一关键字就命中：

```jsonc
{ "match": ["实验报告", "课程笔记"], "dir": "01_课程作业/程序设计", "note": "写进索引说明列" }
```

省略 `rules` 就用内置规则（课程作业 / 课程资料 / 项目 / 演示文稿 / 电子书 / 待清理）。
`dir` 支持 `A/B` 表示层级。没命中任何规则的进 `99_未归类/`，等你补规则。

## 产出物

归档根目录下多一个 `00_索引/`：

- `文件索引.csv` / `文件索引.md` —— 整库快照，每次重写
- `迁移清单.csv` —— 这一批的「原位置 → 新位置 + SHA256」
- `归档日志.jsonl` —— 累积日志，还原脚本按它生成
- `还原到原位置.ps1` —— 把归档里的文件复制回最初位置

还原：

```powershell
powershell -ExecutionPolicy Bypass -File 还原到原位置.ps1
```

## 安全边界

- 方案 6 小时内有效，过期要重新生成。
- `apply` 必须带方案 id 且 `confirm: true`，缺一个就拒绝。
- `copy` 保留源文件；`move` 先校验目标 SHA256 一致再删源文件。

## 安装

包名 `@local/office-archive`，纯 host 工具，没有客户端部分。
在 profile 的 `package.json` 里挂上目录，并加进 `dsh.profile.bundles`：

```jsonc
"@local/office-archive": "link:D:/path/to/dsh_plugs/office-archive"
```

## 配置

`cordis.patch.yml` 里 `config: {}`，没有必填项；分类规则通过每次调用传 `rules` 覆盖。
